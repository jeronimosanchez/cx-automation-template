Paso 5 de 8
Crear versiones
CX crea una versión nueva de cada artefacto con cambios (el flow y cada playbook modificado) y apunta staging a esas versiones. No es una versión única del agente — son varias versiones independientes, una por artefacto.
✋ Acción requerida

Se creará una versión nueva de cada artefacto con cambios detectados en el diff — el flow, y cada playbook modificado, por separado. Las versiones anteriores de cada uno se conservan para poder hacer rollback si los tests fallan.

CX admite 20 versiones por artefacto y el límite es duro: la 21 falla y CX no borra nada por su cuenta. De esas 20, el pipeline gestiona un pool de 5 que rota solo: al crear la sexta, borra la más antigua de las suyas. Las demás son tu reservorio y no se tocan nunca.

Versiones existentes

Etiqueta de este lote de versiones
Letras, dígitos, guiones y guiones bajos. Máx. 64 caracteres. Se usa como displayName en cada versión creada, para poder identificarlas como parte del mismo deploy. Vacío = etiqueta automática con fecha y hora.
